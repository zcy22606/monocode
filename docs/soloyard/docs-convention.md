# 文档规范

- 日期：2026-10-14
- 状态：已确认（v1，SOL-80）
- 关联：SOL-80、SOL-13（文档以文件为准）、SOL-72（product-thinking 增量模式）

底子是用户自己在 `quantitative-trading-agent-service/CLAUDE.md` §4 定的规矩（axis-miner、company-miner 已经在用），Soloyard 补上多仓库、公开文档、凭据，以及应用里怎么显示。原型：`~/Playground/soloyard-prototypes/docs-spec-openroboto.html`（用 openroboto 的真实文档做的）。

## 1. 放在哪

- 每个仓库只有一个 `docs/`。跨仓库、项目级的（产品、整体架构、交接、审计）放**项目根目录**的 `docs/`；只关于一个成员仓库的放那个仓库的 `docs/`。
- 文档页把根目录和所有成员仓库的 `docs/` 汇总显示。项目文件夹最外层、子文件夹里散着的 markdown 由「整理文档」收进来。

## 2. 类型目录

| 目录 | 类型 | 放什么 |
|---|---|---|
| `product/` | 产品 | PRD、需求、立项卡、功能全集、功能卡 |
| `specs/` | 规格 | 接口契约、数据格式、业务规则 |
| `architecture/` | 架构 | 架构设计、技术方案 |
| `adr/` | 决策 | 难以逆转、影响架构或长期成本的决策 |
| `plans/` | 计划 | 开发计划、排期、版本表审查 |
| `research/` | 调研 | 竞品、用户、方法调研，商业分析 |
| `reports/` | 报告 | 实验、事故、审计、进展记录 |
| `runbooks/` | 手册 | 部署、运维、上手、操作流程 |
| `archive/` | 归档 | 被取代或过时的，不删 |

## 3. 文件名

- `NN-中文标题.md`：NN 是该目录里两位递增序号，从现有最大号续编；不用日期前缀，日期写在文件头。
- 标题里的代码标识符、模块名、产品名保持英文原样，比如 `05-π0.5下线与强制新CLI.md`。
- 一组多篇的，整个文件夹编号：`reports/03-文档过期审计/00-总览.md`。
- 引用写「类型/NN」：`adr/03`、`specs/02`；跨仓库时带仓库名。

## 4. 文件头

```markdown
# 标题

- 日期：2026-10-14
- 状态：草稿 / 进行中 / 已确认 / 已结束 / 部分被取代 / 已废弃 / 已归档（后面可以跟一句说明）
- 作者：勇军 / Claude
- 关联：OPE-45、ADR 03、specs/02、D-3
- 取代：（可选）被它取代的文档
```

表格写法（`| **日期** | … |`）和 front matter（`---`）也认。状态只看开头一句归类，后面的复核说明照原文显示。

## 5. 状态和替代

- 被取代的不删：状态改「已废弃」并写明取代者，挪进 `archive/`；已经在 `archive/` 里的保持原名，免得断引用。
- 内容完全相同的副本只留一份，放在按规范该放的位置。
- 文档里分开写事实、决策、计划、假设和没解决的问题，不把猜测写成结论。

## 6. 不算文档 / 不显示的

- **对外材料**（随代码发布给用户的公开文档，给客户、投资人的材料）：保持原名和语言。
- **仓库说明**：README、AGENTS、CLAUDE、CHANGELOG，不改名、不编号。
- **凭据**：`*.secrets*`、`*.credentials*`、`.env*` 文件永不列出、不发给 agent。在文档正文里看到明文密钥（API key、密码、私钥），不复制到别处，单独提醒用户轮换。
- 隐藏目录（`.trellis` 等工具目录）、`node_modules` 不扫。

## 7. 规范写进仓库

每个仓库的 AGENTS.md（只有 CLAUDE.md 的就写在 CLAUDE.md）里有一节「文档约定」，内容是这份规范的要点，让终端里直接跑的 agent、没连 Soloyard MCP 的工具也照着写。「整理文档」时没有的补上；已经有、和这份不一样的，列出差别问用户，不直接改。

## 8. 决策

ADR 是文档，放 `adr/`；产品决策（product-thinking 的 D-x）和一行一条的裁决日志在应用的 Decisions 页。

## 9. Soloyard 里怎么落地

- 数据层 `soloyard/core/src/docs.ts`：`listDocs`（根目录 + 成员仓库的 `docs/`，解析文件头，按 mtime 缓存）、`newDoc`（编号续上、文件头写好）。数据库不存文档。
- agent：MCP `list_docs`（写之前先查同主题的）、`new_doc`（新建一律用它）。规范要点只有一份（`docs.ts` 的 `DOC_CONVENTION`）：MCP 的 instructions 和「整理文档」的提示词都用它；提示词自带全文，因为会话不一定连着 MCP。
- 界面：Docs 页按类型 / 按仓库 / 时间线，已废弃和已归档默认藏起来，不在类型目录里的进「未归类」；「新建文档」走 `newDoc`；「整理文档」开会话让 agent 按规范列清单、用户点头再改（改名同步改引用）。
- 立项卡识别（`stage.ts`）看 `docs/product/` 和 `docs/` 根下文件名带「立项」的。
