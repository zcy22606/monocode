# 手机端和常驻主机技术方案

- 日期：2026-10-16
- 状态：草稿
- 作者：claude-code
- 关联：D-20、D-21、D-22；SOL-86 至 SOL-90；原型 ~/Playground/proof/prototypes/soloyard-mobile-v1/；docs/remote-access.md

## 目标

人不在电脑边时，用手机让 agent 查代码、查库，处理审批，看 issue 和验收；家里放一台常驻主机跑 agent；Mac 照常在本地开发，主机停电不影响 Mac 干活。

## 已定的

- D-20 选 A：做 Android app；家里的 Linux 迷你主机常驻跑 agent；数据留在家里，云上只放中转和备份。
- D-21 选 B：桌面和主机都能干活，代码靠 git 同步，Soloyard 数据之后做双向同步。
- 手机端用 Tauri 2。界面按原型 v1 的 A（项目分栏：会话 / Issues 两栏），新会话、开工、会话里三处都能选模型。

## 现状（查过代码的事实）

- 底座有实验性的远程主机 `host/`（文档 `docs/remote-access.md`）：一个 headless 的 Node 服务，复用全部 provider 适配，有自己的会话库（默认 `~/.monocode-host`）。
  - 只监听 `127.0.0.1:3774`（`--port`、`--data-dir` 可改），只有 `POST /rpc` 一个入口，设备凭据用 `Authorization: Bearer <43 位 token>`，带 `Origin` 头的请求一律拒绝，所以只能从原生 HTTP 调，不能从网页层直接 fetch。
  - 协议版本 `HOST_PROTOCOL_VERSION = 1`，除 `environment.describe` 外每次请求都校验 `environmentId`。
  - 方法：`environment.describe`、`projects.list/browse/open`、`models.list`、`sessions.list/get/update/delete/sync/syncChunk`、`events.read`、`commands.dispatch`（create / configure / send / draft / cancel / approve / answer / compact）、`attachments.*`、`files.*`、`git.*`、`workspace.run`、`devices.revokeSelf`。类型在 `src/features/connections/model/protocol.ts`，纯 TS。
  - `configure` 只能改同一个 harness 的模型、模型设置和权限模式，运行中会被拒绝（桌面端排到这一轮结束再发）。
  - 支持 Linux（systemd 用户服务 + `loginctl enable-linger`，不用登录桌面）、macOS、Windows；发布包自带 Node。
- 桌面端经「设置 → Connections」用 SSH 连主机，RPC 走 Rust 的 `ureq`（`src-tauri/src/remote.rs`）。会话同步是轮询：跑着时 0.75 秒一次，闲时 3 秒，只拿变了的块。
- Soloyard 自己的数据层（`soloyard/core`）、MCP、issue、验收合并都只认本机，不认识主机上的项目。
- 本机开发环境（2026-10-16 查）：Android SDK（platforms 35 / 36、NDK 27.1、adb）、JDK 22、Node 24、Tailscale 1.102（支持 `serve --tcp`）都在；Rust 还没装 Android 编译目标；没有 Android Studio。

## 架构

```
                       Tailscale（只对自己的设备）
Android app ───────────────────────────────> 网关 soloyard-host（新）──> monocode-host（底座）127.0.0.1:3774
                                               │  手机唯一的入口：配对、转发主机接口、会话镜像、（之后）issue
Mac 桌面 Soloyard ─数据进程推会话镜像────────────┘
                 ─SSH 隧道（底座的远程连接）──────────────────────────> monocode-host
主机上：Claude Code / Codex、公司仓库、数据库只读账号
国内云服务器（需要时）：自建 Tailscale 控制和中继（Headscale + DERP）+ ntfy
```

2026-10-16 改：原来手机直连 monocode-host，电脑上的会话手机看不到。改成主机上加一个 Soloyard 网关：

- **网关**（`soloyard/host/`，Node 零依赖）：手机只连它，一个地址、一个凭据。`soloyard.*` 方法自己处理，其余原样转给 monocode-host（用网关自己的主机凭据），monocode-host 只对本机开放。
- **会话镜像**：桌面的 Soloyard 数据进程（`soloyard/core` 的 sidecar，本来就开着 `monocode.db`）每隔几秒把变了的会话推给网关；手机上看到「主机上的」和「电脑上的」两组，电脑上的只读。
- **项目对应**：Mac 和迷你主机上的路径不一样，按 git 远程地址（没有就用文件夹名）对上。
- **接着干**：电脑上的会话在主机上接着干 = 主机新建会话时带上原来的 provider 会话 id 和对话记录（monocode-host 的 `create` 要加这个口子，提给上游）、把 provider 转录文件拷过去、按 git 快照把代码带过去；之后电脑上那份变只读。

### 手机 app：`mobile/`（新）

- 单独的 Tauri 2 项目（自己的 `Cargo.toml`、`tauri.conf.json`、Android 工程），不碰桌面端的 `src-tauri`，和上游没有冲突面。
- 前端用同一套 React + Vite + Tailwind。直接复用 `protocol.ts`（协议类型、`applySessionSync`）、会话的类型定义和 `src/i18n`；对话渲染能不能复用桌面的组件，开工时评估，不能就写一份手机版。
- Rust 层只做一件事：`host_rpc(method, params)`，用项目里已有的 `ureq` 发 `POST /rpc`，带 token、协议版本和 `environmentId`。网页层拿不到 token。token 先存在 app 私有目录（Android 沙盒），之后换 Android Keystore。
- 连接：主机只开 loopback。主机上跑 `tailscale serve --tcp 3774 tcp://127.0.0.1:3774`，只有自己 tailnet 里的设备能连；HTTP 本身是明文，但走在 WireGuard 隧道里。Android 默认不许明文 HTTP，网络安全配置里只放行 `ts.net` 域名。
- 同步：照桌面端轮询；app 在后台时不拉，靠推送。
- 推送：主机上 Claude Code 的 `Stop` / `Notification` hook、Codex 的 `notify` 调 ntfy（自建在云服务器上），手机装 ntfy。不接 Google 的推送（国内用不了）。

### 主机（Linux 迷你主机）

- 装底座的主机包，不改代码，不装桌面界面。Mac 桌面在「设置 → Connections」填 SSH 地址会自动装好并配对。
- 阶段 2 起加 `soloyard/host/`（Node，零依赖，复用 `soloyard/core`）：在主机上跑 Soloyard 数据层和 issue 接口，监听 `127.0.0.1:3775`，由 systemd 管。

### 桌面（Mac）

- 阶段 1 不改代码。
- 阶段 2、3 加数据同步、会话备份和接手（新文件为主，上游挂载点在 `App.tsx`、`SessionPane.tsx`）。

## 分阶段计划

| 阶段 | 内容 | 主机 | 工作量 |
|---|---|---|---|
| 1 手机 app 能用 | 配对；项目和会话列表；实时对话；输入框和选模型；审批、回答、停止；新会话；通知（hook + ntfy） | 先用 Mac 代替 | 2–3 周 |
| 2 Soloyard 数据上主机 | `soloyard-host`；数据双向同步（按条以后改的为准）；手机 Issues 栏：列表、详情、开工、通过 / 打回、新建 | 迷你主机 | 3–4 周 |
| 3 会话和代码接力 | 每轮结束推备份（对话、agent 转录、代码快照）；接手 / 移交；主机协议加「导入会话」（给上游提 PR） | 迷你主机 | 3–4 周 |
| 4 看文件和 diff | 主机已有接口，只做界面 | | 1 周 |

阶段 2 和 3 的先后可以换：更常在手机上看 issue 就先 2，更常把 Mac 上的会话挪到手机上接着干就先 3。

2026-10-16：用户试用后最先要的是在手机上看到电脑上的会话，先做 3 的前半段，按这个顺序：

1. 网关：配对、转发主机接口、会话镜像的存取（SOL-86）
2. 桌面数据进程推会话镜像，设置里配网关（SOL-87）
3. 手机上看电脑的会话（只读）（SOL-88）
4. 在主机上接着电脑的会话：主机导入会话（上游 PR）、拷转录、代码快照（SOL-89）
5. 电脑拿回手机上的会话接着聊（SOL-89 同一批做的）
6. 之后：Soloyard 数据上主机和 Issues 栏、通知

### 三端怎么分工（D-22，2026-10-16 定）

**手机永远只是遥控器；每个会话只有一份，在一台机器上跑；手机和另一台都只同步它。**

- **会话在哪跑按会话定**：Mac 上开的默认在 Mac 上跑（碰本地文件、本地软件、本地预览的体验不变）；重活、长时间的、手机上开的放服务器。服务器像一个 24 小时的同事：在自己那份代码的分支 / 工作树上干，干完在 Mac 上验收合并（就是 Soloyard 现有的 issue → agent → 验收）。
- **手机发消息给跑这个会话的那台**：
  - Mac 上的会话：网关 `soloyard.mirror.send` 排进 Mac 的收件箱；Mac 上的 Soloyard 每 2 秒 `soloyard.relay.pull` 取一次（15 秒内来过算在线），`useRelayInbox` 用 `requestSendToSession` 发进那个会话，和在 Mac 上打字一样，「进行中」「已完成」、用时都是原生的。Mac 不在线（睡着了 / 没开 Soloyard）时手机上只能看。
  - 服务器上的会话：手机直接经网关转给服务器上的主机服务。
- **实时同步**：底座只在一轮开始和结束时存盘，数据进程每 5 秒把变了的整份推给网关；正在跑的这一轮由界面从内存里拿，每个会话最多每秒推一次（`liveMirror.ts` → `soloyard.mirror.live`），网关盖在整份上面（`overlay`），手机每 1.5 秒取一次。
- **服务器到了以后要做**（迷你主机到了再调）：
  - 「放到服务器上跑」和会话搬家：对话（provider 转录）+ 没提交的改动（临时分支）一起搬，空闲时才搬。主机协议的 `create` 已经能带 `import`（provider 会话 id + 对话）建会话（`host/engine.ts`，之后给上游提 PR），网关的 `soloyard.mirror.continue` 是它的雏形，搬代码和转录还没做。
  - 两台路径一致：服务器上建 `/Users/zcy22606` 链到用户目录，仓库放同样的位置，对话记录、配置、搬家都不用改路径。
  - 共享文件夹（比如 `~/Soloyard-files`，用 Syncthing 走 Tailscale 同步），agent 往这里写的东西两边都有。
  - Mac 上看服务器上的会话：会话列表顶上「在手机上」那栏（`HostSessions.tsx`，经网关 `soloyard.host.list / take`），以后改成按机器标注、和本地会话放一起。
  - Soloyard 自己的数据层（issue、文档、多仓库、验收合并、MCP）上服务器，服务器上的项目才能用这些功能。
- **手机端还要加**：对话里的文件点了能下载，弹安卓的分享菜单发到微信 / 飞书。
- **网络**：手机现在经 Tailscale 旧金山中继（来回 0.5–1 秒）。家里没开 IPv6（`tailscale netcheck`：IPv6 no）；先在光猫 / 路由器开 IPv6 试直连，不行再租国内云服务器自建 DERP 中继。

**改掉的第一版**：手机在电脑会话里发消息时，让服务器拿着对话另起一份接着跑。试用下来同一段对话变成两份：手机要跳页重新加载，Mac 上看不到「进行中」「已完成」和用时，还要猜哪份最新。已经去掉。

## 试用版：不等迷你主机

- **Mac 当主机**：`node build/host/monocode-host.mjs start --data-dir ~/.soloyard-host-trial`，再 `pair --name Android` 拿凭据。不装开机服务，Mac 合盖或关机就停。
- **网络**：手机装 Tailscale，和 Mac 登同一个账号；Mac 上跑 `tailscale serve --tcp 3774 tcp://127.0.0.1:3774`。
- **安装**：打 debug APK，用 adb 装，或者把 APK 传到手机上装。
- **换到迷你主机**：在 Linux 上装好主机包，手机里把地址换成迷你主机的。不用改代码。
- 试用期间 Mac 主机上的会话和桌面本地会话是两套。桌面可以在「设置 → Connections → 按 URL 连接」连 `http://127.0.0.1:3774` 看到它们。

## 风险

- 国内移动网络下 Tailscale 可能打洞失败、走海外中继，慢或连不上。阶段 1 用下来不行就租国内云服务器自建中继。
- 主机是上游的实验功能，更新快；协议版本变了，手机端要跟着改。
- 本机是 JDK 22，Android 的 Gradle 构建可能不认，需要另装 JDK 21。（实测 Gradle 8.14.3 + JDK 22 能构建，没另装。）

## 还没定的

- `soloyard-host` 的鉴权：已定为另配一套——网关自己发手机 / 电脑两类设备凭据，转发主机服务时换成网关自己的主机凭据。
- 手机上 token 的安全存储：Android Keystore 要不要加 Tauri 插件（新依赖，先问）。
- 对话渲染：已定为重写（手机上的块渲染 `mobile/src/screens/blocks.tsx`，Markdown 用 streamdown，表格 / 代码块样式照桌面）。

## 不做的

- Linux 桌面界面：主机只跑后台服务。
- iOS。
- Google 推送（FCM）。
- 两台机器同时往同一个会话发消息。
